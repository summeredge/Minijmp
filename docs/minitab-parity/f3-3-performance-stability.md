- 性能基准实测 6 组规定规模，确认每次导入后的真实行列数。500k × 20 案例以可见 Tk 窗口运行；其他用例同样创建完整 Tk 应用并用 `after` 心跳记录主线程间隔。
- CSV 100k × 20 峰值工作集增量从 217 MiB 降至 64 MiB；500k × 20 和 1m × 10 原先因上限差一行被拒，当前都成功且峰值工作集增量分别约 279 MiB、291 MiB。

## 4. F3-3C 大数据工作表显示与编辑

### 基线与修改

使用固定种子数据，在 MiniJMP `MTable` 的真实 Tk 工作表中测 100k × 20、500k × 20；另测 1k × 5,000 宽表。操作包括首次显示、垂直/水平滚动、定位、视口重绘、切换工作表、单格编辑、撤销/重做、排序、筛选、2×2 复制粘贴和列公式重算。

| 场景 | 操作 | 修改前 | 修改后 | 观察 |
|---|---|---:|---:|---|
| 100k × 20 | 首次显示 / 视口重绘 | 36 / 14.5 ms | 47 / 12.2 ms | 保持同一量级；可见窗口运行首次显示 97 ms |
| 100k × 20 | 单格编辑 / 撤销 / 重做 | 35 / 26 / 27 ms | 28 / 18 / 13 ms | 单格快照峰值工作集增量约 16 MiB → 0.7 MiB |
| 500k × 20 | 首次显示 / 视口重绘 | 36 / 10.8 ms | 44 / 11.3 ms | 重绘约 11 ms；滚动和末格定位均约 0.1–1.2 ms |
| 500k × 20 | 建立撤销快照 | 13.1 ms | 0.2 ms | 快照额外工作集约 76 MiB → 0 |
| 500k × 20 | 单格编辑 / 撤销 / 重做 | 39.8 / 67.0 / 28.9 ms | 31.2 / 13.5 / 15.2 ms | 编辑额外工作集约 80 MiB → 3.9 MiB；撤销约 153 MiB → 0 |
| 500k × 20 | 排序 / 筛选 / 2×2 粘贴 / 公式重算 | 101 / 55 / 31 / 279 ms | 86 / 43 / 17 / 225 ms | 公式结果通过校验；全表操作仍处理完整数据 |
| 1k × 5,000 | 首次显示 / 视口重绘 / 水平滚动 | 未测 | 72 / 44 / 0.5 ms | 当前全列位置与网格线工作未构成长时间阻塞 |

每次确认更改时，MTable 原先深拷贝完整 DataFrame，undo/redo 又深拷贝恢复值。项目锁定 pandas 3.0.6，其 Copy-on-Write 保证浅副本间的写入隔离；历史记录及恢复改用浅副本，筛选保留的全表也改用浅副本。历史长度仍限制为 5，所有操作仍走原有表格接口。

### F3-3C 定向验证

- 相关联合回归 `tests/test_table_regressions.py`、`tests/test_worksheet_formulas.py`、`tests/test_worksheets.py`：**272 passed、3 skipped**。补正通用对话框烟测夹具，为三个需要 `kind` 的对话框提供当前构造参数，保留全部构造覆盖。
- 100k × 20 和 500k × 20 全流程中，工作集峰值增量从约 145 / 771 MiB 降至约 78 / 372 MiB；500k 私有内存峰值增量从约 843 MiB 降至两次实测中位数约 418 MiB。Tk 主线程最大观察间隔约 0.32 s 降至约 0.29 s；100k 可见窗口实测为 0.14 s。
- **无需改动可见区域绘制或表格组件结构。** 100k、500k 高表的首次显示约 36–47 ms、可见区重绘约 11–15 ms；1k × 5,000 宽表重绘约 44 ms。现有实现已只格式化和绘制可见单元格，且不做自动全列宽扫描。

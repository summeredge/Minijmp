## 基准方法和复现

解释器：项目 `.venv/Scripts/python.exe`，Python 3.11.9；Pillow 13.0.0、openpyxl 3.1.5。未使用 Codex bundled runtime，未安装/升级依赖。

```powershell

& $python tools/benchmark_report_rendering.py --source-dir docs/g14-evidence/before --output docs/g14-evidence/baseline
& $python tools/benchmark_report_rendering.py --output docs/g14-evidence/after
# 只重放 GUI 阶段，或通过 --scenario huge 指定一个场景。
& $python tools/benchmark_report_rendering.py --phase gui --output docs/g14-evidence/after
```

每个场景分别运行 exports 和 GUI 子进程；导入和输入数据准备不计入 StatTable 构建时间。GUI 计时从向已经创建的结果窗口输出表格开始，到完成 Tk `update()` 为止，属于自动化首次呈现指标，并非人眼可见时间或输入到屏幕的物理延迟。20 张表的构建/显示/导出时间均为总和，每张 100×7；Excel 是 20 个独立文件，与逐表导出行为一致。

GUI 子进程默认总时限 20 秒，包含导入、构建和 GUI 初始化；exports 总时限 90 秒。超时中止整个工作进程树。**不能把 20 秒进程超时当作首次显示耗时的精确下界。** 完成不了的首次显示、控件数、滚动及 GUI 保存指标均保留为未测得。

滚动：调用报告 Text 纵向滚动和分页 Treeview 的纵横滚动，每次等待 Tk 更新，12 次取中位数/最大值。内存：Windows `GetProcessMemoryInfo`，单位 MiB，记录当前/峰值工作集及进程提交量；父进程约每 100 ms 采样实际工作进程的峰值工作集。统计库导入、输入和构建暂存数据也计入进程峰值。超时/失败场景的峰值只是中止前观测值，不能视作完整渲染所需内存。

修改前首次六组测量在生产代码修改前完成。开发中修正了基准工具的 Windows 句柄类型及虚拟环境重定向器 PID 采样问题；GUI 阶段随后使用原始快照重放，以取得正确的进程内存。下表使用最终有效 JSON，不使用早期错误的重定向器内存读数。exports 保留最初修改前数据。原始记录见 `g14-evidence/baseline/`、`after/`，合并数据见 `g14-evidence/performance.csv`。

这些是本机单次有效测量，未进行多机或统计显著性分析；毫秒级写盘和小表差异不作为性能改善结论。

## GUI 复核与限制

沿用项目 ttk 主题，仓库没有 `DESIGN.md`。使用 GUI engineering 技能及原生桌面/testing 参考。已实际创建 Windows Tk 窗口、检查控件和保存截图，并复核小表、50,000 行首页/末页、480×320 窗口与连续多表；见 `g14-evidence/*window.png`、`large-first-page.png`、`large-last-page.png`。最小窗口通过原报告外层滚动访问超出视口的表格和分页区域，底部清空/保存/复制/全选保持可见。

这是脚本驱动的真实 GUI 检查和截图目视复核。人工鼠标拖拽、触控板手感、读屏和全部 Windows DPI/主题组合未验证；不将自动滚动时间描述为人工体验测试。

仍有以下界限：

- StatTable 保留完整字符串、原始值和显示值，构建和基础存储仍为 O(行×列)；本机 50,000×7 构建约 3.4 秒。更大规模若需要消除此开销，需单独评估旧字符串协议和报告生产端。
- Excel 仍使用原有完整 openpyxl 工作簿并同步导出；50,000 行约 23.6 秒，期间可能阻塞 GUI。需要进一步改善导出交互时，可单独评估流式工作簿/可取消导出，不在本次增加通用线程框架。
- 分页 Treeview 的列仍全部创建，当前验证到 100 列；极端列数和超长单元格仍有 Tcl 字符串/列管理成本。单页 1,000 单元格预算在列数超过 1,000 时至少保留一行。
- 连续多表控件仍随表张数增长，但表格数据行数不再决定大表控件数；未承诺无限张报告常驻窗口。
- 自动化整幅跳转滚动中，20 表场景最慢一次约 1.245 秒，100 列宽表约 0.625 秒；仍有小表原生 Label 布局和宽列绘制成本，没有承诺所有滚动均小于一帧。
- PNG 内存只是保守估算，安全阈值不能保证任意机器的可用内存。超限时使用完整 Excel/TXT。

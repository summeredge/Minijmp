## 文件语义

“保存/另存为”保存整个 `.dexpl` 工程；“导出当前表（单表 / Excel）”可导出 `.pickle`、`.xlsx`、`.csv`。原“导出 CSV”仍针对当前表。打开 `.pickle` 会读取单表数据成为未命名工程，不会将工程保存误写到原 pickle 文件。

CSV 智能/高级导入保留原检测、预览及参数界面；Excel 导入全部 Sheet；PI 保留原查询界面及时间/数值转换。导入均创建新表并自动处理重名，保留初始默认空表。取消和读取/建表失败不会增加标签或覆盖其他表。

`.dexpl` 使用既有 gzip+pickle 的 `{表名: {table, meta}, meta: 工程信息}` 结构，按插入顺序保存，记录活动表、列宽和 MTable 显示设置。忽略旧 DataExplore 的不兼容表元数据。保存筛选表时使用完整源数据且不清除当前筛选。读取先校验并构建所有表，再替换旧工程；保存使用同目录临时文件、flush/fsync 和原子替换。打开前提示只读取可信 pickle 文件。

## 手工复现

1. 使用项目解释器启动 `code/MiniJMP.py`，通过“工作表”菜单新增两张表，分别输入不同数据；复制其中一张，修改副本后回到原表检查数据和撤销互不影响。
2. 重命名为已有名称或含 `/` 的名称，确认拒绝；取消删除后数据不变。连续删除到最后一张，确认自动保留一张安全空表。
3. 在一张表执行描述统计和时间序列图；各标签的数据分别分析，确认结果和曲线对应来源。程序测试还直接切换已打开对话框后的活动表，验证原来源绑定。
4. 导入 CSV、高级 CSV、含多 Sheet 的 Excel 和 PI 数据，检查新标签、重名后缀，以及原表内容不变。取消或制造无效路径，检查无多余标签。
5. 将三表保存为 `.dexpl`，关闭后重新打开，检查标签顺序、活动表、dtype、列宽和精度。打开旧 `.pickle`，确认仅有一张导入表，保存工程时仍要求 `.dexpl`。
6. 修改数据后新建、打开其他工程或退出，分别验证保存/不保存/取消；在保存文件选择框取消，原工程保持打开。

## 范围与限制

不做跨表公式/引用、跨表聚合或模型重写。工程不保存编辑历史、过滤表达式、已打开的分析对话框/结果/图形；数据、标签、活动表和所需显示设置可恢复。删除来源表后的旧对话框受到防误用保护，需关闭并从现存表重新打开。PI 回归使用测试读取器，未连接真实 PI SDK/生产服务器；未验证真正的 200% DPI 和 Windows 多显示器 DPI 切换。
